# 웹서비스 수용 테스트

1. README와 과제 요구사항에서 필수 사용자 흐름 및 완료 기준을 추출한다.
2. 각 기능별로 정상 입력, 빈 값, 잘못된 입력, 오류 상황을 간단한 테스트 목록으로 정리한다.
3. 현재 프로젝트에 존재하는 빌드·테스트 명령을 먼저 확인한다. 없는 명령을 임의로 실행하지 않는다.
4. 필요하다면 제공된 로컬 하네스 `harness/web-check.sh`를 참고하되, 실행 전 스크립트 내용과 작업 환경을 확인한다.
5. 로컬 HTTP 응답 확인은 화면·상호작용 전체 테스트와 구분한다.
6. 브라우저 자동 조작이 금지된 환경에서는 해당 도구를 사용하지 않고 허용된 미리보기에서 수동 검증 절차를 안내한다.
7. 실패한 검사는 원인을 추적하고 수정·재실행 여부를 분명히 한다.
8. 실행 증거가 없는 테스트는 ‘미검증’으로 표시하고, 실제 결과를 꾸며내지 않는다.

## 결과 형식
| 기능/요구사항 | 확인 방법 | 실제 관찰 결과 | 판정(통과/실패/미검증) |
|---|---|---|---|

- 실행 명령과 환경·포트
- 변경한 파일이 있다면 변경 내역
- 남은 핵심 위험과 수동 확인 항목

## 안전 및 범위
- 테스트 계획만 요청받으면 프로젝트 파일을 변경하지 않는다.
- 외부 호스트 전송, 외부 AI 및 허용되지 않은 Computer Use 기능을 사용하지 않는다.
- 로그나 출력에 비밀정보가 포함되면 마스킹한다.
