# API 연동

1. 기존 API 라우트, HTTP 메서드, 요청·응답 구조, 인증 요구사항을 코드와 명세에서 확인한다.
2. 확인하지 못한 엔드포인트나 응답 필드를 추측하여 정상 동작한다고 가정하지 않는다.
3. 필수 사용자 흐름부터 연결하고 성공·로딩·빈 결과·오류 상태를 각각 처리한다.
4. 요청 본문과 입력값을 필요한 범위에서 검증하며, 서버 쪽 인가 검증을 클라이언트 처리로 대신하지 않는다.
5. 민감한 키와 토큰은 코드에 하드코딩하지 않고 제공 환경의 안전한 설정을 따른다.
6. 타임아웃, 실패 응답, 네트워크 오류에 대해 사용자에게 이해 가능한 상태를 표시한다.
7. 실제 API 서버가 있으면 허용된 로컬 주소에서 상태 코드와 응답 구조를 검사한다.
8. 외부 전송이 제한된 환경이라면 외부 API를 호출하지 말고 로컬 모의 데이터 또는 허용된 API만 사용한다.

## 결과 형식
- 실제 확인한 API 계약과 변경 파일
- 성공·실패·예외 처리 방식
- 실행한 요청·테스트의 상태와 근거
- 가정·미검증 사항과 위험

## 안전 및 범위
- 연동 계획이나 계약 검토만 요청되면 파일을 변경하지 않는다.
- 요청·응답 로그에서 개인정보, 비밀번호, 토큰, API 키를 마스킹한다.
- 금지된 외부 서비스로 작업 자료를 전송하지 않는다.
