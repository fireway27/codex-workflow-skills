# 기술적 의사결정 기록

1. 기록할 결정과 관련 요구사항을 명확히 한다.
2. 검토한 대안과 선택한 접근법의 이유를 정리한다.
3. 구조·구현상의 장단점과 트레이드오프를 쉬운 말로 설명한다.
4. 가능한 경우 코드, 테스트, 로그 등 실제 관찰된 근거를 연결한다.
5. 사실, 가정, 미해결 불확실성을 구분한다.
6. 실제 발생한 실패, 수정 조치, 재검증 결과를 기록한다.
7. 알려진 한계와 후속 작업을 정리한다.
8. 수행하지 않은 작업, 테스트, 결정이나 대화를 꾸며내지 않는다.
9. 이전 대화를 보지 않은 유지보수자도 이해할 수 있게 간결하게 작성한다.

## 결과 형식
- 결정 사항과 배경
- 검토한 대안 및 선택 근거
- 실제 검증 증거와 결과
- 트레이드오프·한계·다음 단계

## 공통 실행 및 검증 원칙
- 중요한 변경 전에는 목적과 기대 결과를 간결히 밝힌다.
- 계획, 구현, 검증 단계를 구분하되 불필요한 승인 요청이나 반복 보고로 작업을 지연하지 않는다.
- 실제 변경한 파일과 실행한 명령을 정확히 보고한다.
- 검증된 결과와 추정·미확인 사항을 명확히 구분한다.
- 오류가 발생하면 관찰된 증상 → 원인 가설 → 수정 → 재검증 순서로 설명한다.
- 중요한 기술 선택은 이유와 대안을 간단히 설명한다.
- 작업 기록·테스트 결과·의사결정을 조작하거나 꾸며내지 않는다.
- 불필요한 도구 호출과 반복 설명을 줄인다.
- 외부 도구 설치, 데이터 전송, 큰 범위의 변경은 현재 환경의 정책과 사용자 승인을 확인한다.

- 실제 작업 당시의 기록과 사후에 제안한 내용을 명확히 구분한다.
- 명령 출력과 오류 로그를 보고할 때 API 키, 토큰, 비밀번호, 개인정보를 마스킹한다.
- 분석·계획·검토만 요청한 경우 프로젝트 파일을 수정하지 않는다.
- 실행한 테스트와 실행하지 않은 테스트를 구분한다.
- 중요한 작업은 실행 명령, 관찰 결과, 수정 내용, 검증 결과를 간결하게 보고한다.
- 허용되지 않은 외부 데이터 전송이나 원격 저장소 업로드를 수행하지 않는다.
