# 코드 품질 검토

1. 판단하기 전에 관련 소스 파일과 변경 내역(diff)을 확인한다.
2. 정확성 결함, 보안 취약점, 데이터 손실 위험, 회귀 가능성을 우선한다.
3. 입력값 검증, 예외 처리, 자원 사용, 비밀정보 취급을 점검한다.
4. 가독성, 모듈화, 중복, 유지보수성을 평가한다.
5. 확인된 결함, 잠재적 위험, 스타일 선호를 구분한다.
6. 가능하면 심각도, 파일 위치, 재현 방법을 포함해 문제를 제시한다.
7. 최소 수정안과 수정 후 검증 절차를 함께 제안한다.
8. 사용자가 요청하지 않았다면 코드를 직접 변경하지 않는다.
9. 명시적 승인 없이 프로젝트 내용을 외부 서비스에 전송하지 않는다.

## 결과 형식
- 검토 범위와 확인한 근거
- 심각도별 발견 사항(확정/가능성 구분)
- 권장 수정안과 검증 방법
- 검토하지 못한 범위와 남은 위험

## 공통 실행 및 검증 원칙
- 중요한 변경 전에는 목적과 기대 결과를 간결히 밝힌다.
- 계획, 구현, 검증 단계를 구분하되 불필요한 승인 요청이나 반복 보고로 작업을 지연하지 않는다.
- 실제 변경한 파일과 실행한 명령을 정확히 보고한다.
- 검증된 결과와 추정·미확인 사항을 명확히 구분한다.
- 오류가 발생하면 관찰된 증상 → 원인 가설 → 수정 → 재검증 순서로 설명한다.
- 중요한 기술 선택은 이유와 대안을 간단히 설명한다.
- 작업 기록·테스트 결과·의사결정을 조작하거나 꾸며내지 않는다.
- 불필요한 도구 호출과 반복 설명을 줄인다.
- 외부 도구 설치, 데이터 전송, 큰 범위의 변경은 현재 환경의 정책과 사용자 승인을 확인한다.
