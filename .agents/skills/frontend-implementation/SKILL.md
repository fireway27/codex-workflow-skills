# 프론트엔드 구현

1. 과제 설명과 기존 프로젝트 구조, 프레임워크, 디자인 제약을 먼저 확인한다.
2. 필수 화면과 사용자 흐름, 완료 조건을 구분한다. 요구되지 않은 기능을 임의로 추가하지 않는다.
3. 기존 UI 패턴과 의존성을 재사용하고, 필요 없는 새 라이브러리를 설치하지 않는다.
4. 의미 있는 HTML 요소, 연결된 입력 레이블, 키보드 접근성, 오류 상태를 고려한다.
5. 모바일·데스크톱 너비에서 레이아웃이 무너지지 않도록 반응형 동작을 구현한다.
6. 로딩·빈 결과·오류 상태를 실제 요구사항에 맞게 처리한다.
7. 구현 후 프로젝트에 정의된 빌드·린트·테스트만 실행하고 결과를 보고한다.
8. 화면을 실제로 열어 확인하지 않았다면 시각적 검증을 완료했다고 말하지 않는다.

## 결과 형식
- 구현한 화면과 변경 파일
- 선택한 구조와 주요 이유
- 실제 실행한 검사·확인 결과
- 미검증 동작과 남은 제약

## 안전 및 범위
- 분석이나 디자인 검토만 요청된 경우 코드를 변경하지 않는다.
- 허용되지 않은 브라우저 자동 조작이나 외부 AI 연결을 사용하지 않는다.
- 민감정보·인증 토큰을 코드나 로그에 노출하지 않는다.
