# 테스트 및 디버깅

1. 프로젝트 언어, 실행 환경, 의존성, 기존 테스트 명령을 확인한다.
2. 가능한 경우 코드 수정 전에 문제를 재현한다.
3. 실제 오류 메시지, 영향받는 동작, 재현 절차를 기록한다.
4. 원인 가설을 세우고 관련 코드·명령·테스트로 검증한다.
5. 근거가 있는 최소 수정만 수행하고 무관한 리팩터링은 피한다.
6. 실패했던 테스트와 관련 회귀 테스트를 다시 실행한다.
7. 실제 실행한 테스트와 제안만 한 테스트를 명확히 구분한다.
8. 실행 명령, 관찰된 결과, 남은 실패와 한계를 보고한다.
9. 실행 근거 없이 문제가 해결됐다고 주장하지 않는다.

## 결과 형식
- 증상과 재현 조건
- 실행 명령 및 실제 결과
- 원인 가설과 확인 근거
- 수정 파일·변경 요약
- 재검증 결과와 미해결 문제

## 공통 실행 및 검증 원칙
- 중요한 변경 전에는 목적과 기대 결과를 간결히 밝힌다.
- 계획, 구현, 검증 단계를 구분하되 불필요한 승인 요청이나 반복 보고로 작업을 지연하지 않는다.
- 실제 변경한 파일과 실행한 명령을 정확히 보고한다.
- 검증된 결과와 추정·미확인 사항을 명확히 구분한다.
- 오류가 발생하면 관찰된 증상 → 원인 가설 → 수정 → 재검증 순서로 설명한다.
- 중요한 기술 선택은 이유와 대안을 간단히 설명한다.
- 작업 기록·테스트 결과·의사결정을 조작하거나 꾸며내지 않는다.
- 불필요한 도구 호출과 반복 설명을 줄인다.
- 외부 도구 설치, 데이터 전송, 큰 범위의 변경은 현재 환경의 정책과 사용자 승인을 확인한다.
