# 요구사항 분석

1. 제공된 명세, README, 관련 파일을 먼저 읽는다.
2. 명시된 요구사항과 추정·제안을 구분한다. 자료에 없는 내용을 임의로 확정하지 않는다.
3. 사용자·이해관계자, 목표, 입력·출력, 제약조건, 제외 범위를 파악한다.
4. 필수 요구사항과 선택적 개선사항을 분리한다.
5. 각 필수 요구사항에 대해 관찰 가능한 완료 기준과 예외 상황을 정의한다.
6. 모호한 사항과 확인 질문을 정리하고, 진행 가능한 부분과 보류할 부분을 구분한다.
7. 가능한 경우 근거 파일·위치를 포함한 요구사항 표로 요약한다.
8. 명시적인 요청이 없으면 구현 파일을 수정하지 않는다.

## 결과 형식
- 분석한 자료와 확인 범위
- 목표·필수 요구사항·제약조건
- 요구사항별 완료 기준 및 검증 방법
- 미확인 사항과 다음 단계

## 공통 실행 및 검증 원칙
- 중요한 변경 전에는 목적과 기대 결과를 간결히 밝힌다.
- 계획, 구현, 검증 단계를 구분하되 불필요한 승인 요청이나 반복 보고로 작업을 지연하지 않는다.
- 실제 변경한 파일과 실행한 명령을 정확히 보고한다.
- 검증된 결과와 추정·미확인 사항을 명확히 구분한다.
- 오류가 발생하면 관찰된 증상 → 원인 가설 → 수정 → 재검증 순서로 설명한다.
- 중요한 기술 선택은 이유와 대안을 간단히 설명한다.
- 작업 기록·테스트 결과·의사결정을 조작하거나 꾸며내지 않는다.
- 불필요한 도구 호출과 반복 설명을 줄인다.
- 외부 도구 설치, 데이터 전송, 큰 범위의 변경은 현재 환경의 정책과 사용자 승인을 확인한다.
