# 작업 계획 및 분해

1. 요구사항과 현재 저장소 구조를 확인한다.
2. 필수 요구사항을 충족하는 가장 작은 동작 가능한 결과물을 정의한다.
3. 작업을 입력·출력·완료 조건이 명확한 작은 단위로 나눈다.
4. 작업 간 의존성, 통합 지점, 예상 실패 요인을 표시한다.
5. 선택적 꾸미기보다 정확성과 핵심 기능을 우선한다.
6. 빌드·실행·테스트·통합·문서화 작업을 계획에 포함한다.
7. 예상 시간은 추정치임을 밝히고 실제 진행 상황에 따라 조정한다.
8. 진행 상태를 완료·진행 중·차단·미검증으로 구분한다.
9. 파괴적 변경이나 광범위한 구조 변경 전에 사용자 확인을 받는다.

## 결과 형식
- 구현 목표와 최소 완료 범위
- 우선순위별 작업 목록(의존성·완료 조건 포함)
- 주요 위험 및 대안
- 단계별 검증 계획
- 현재 진행 상태와 다음 작업

## 공통 실행 및 검증 원칙
- 중요한 변경 전에는 목적과 기대 결과를 간결히 밝힌다.
- 계획, 구현, 검증 단계를 구분하되 불필요한 승인 요청이나 반복 보고로 작업을 지연하지 않는다.
- 실제 변경한 파일과 실행한 명령을 정확히 보고한다.
- 검증된 결과와 추정·미확인 사항을 명확히 구분한다.
- 오류가 발생하면 관찰된 증상 → 원인 가설 → 수정 → 재검증 순서로 설명한다.
- 중요한 기술 선택은 이유와 대안을 간단히 설명한다.
- 작업 기록·테스트 결과·의사결정을 조작하거나 꾸며내지 않는다.
- 불필요한 도구 호출과 반복 설명을 줄인다.
- 외부 도구 설치, 데이터 전송, 큰 범위의 변경은 현재 환경의 정책과 사용자 승인을 확인한다.
